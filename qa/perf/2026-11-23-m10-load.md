# Load test — 200 concurrent matches (milestone 10)

Tool: `npm run loadtest -- --matches 200 --workers 4 --seconds 30` (`server/scripts/loadtest.ts`).
Each match runs the real `Match` at 64 Hz with **10 synthetic human clients** (random-walk movement,
firing ~15 % of ticks, one input per tick). Every outgoing message is encoded with the real codec, so
fog-of-war line of sight, snapshot building and encoding are included. Bot-only matches skip those
and understate cost.

Machine: cloud container, 4 vCPU, 15 GB. A software-rendered (lavapipe) screenshot job ran at the
same time and took over a core, so the 200-match numbers are pessimistic.

## Optimisation found by the test

A profile of 10 matches showed fog-of-war line of sight (`segmentBlocked` + `rayBox`) at **53 %** of
tick time. `Match.canSee` now reuses results over time:
- A visible result holds for 3 ticks. This stays inside the existing 6-tick send grace window.
- A hidden pair is rechecked every 2nd tick. The 2-tick + ping lead margin already hides that delay.
- The cache is cleared whenever a smoke or wall appears, grows or ends.

Sight sampling no longer allocates per call.

| | before | after |
|---|---|---|
| per match-tick, isolated (10 matches, 1 thread) | 0.324 ms | **0.180 ms** |

## 200 matches × 10 clients, 4 workers (shared CPU)

| | before | after |
|---|---|---|
| worker tick avg (50 matches each) | 29.4 ms | 18.0 ms |
| late ticks | 80 % | 38 % |
| egress | 86 Mbit/s | 129 Mbit/s (more ticks delivered) |
| per client | — | 64 kbit/s |
| peak RSS (all workers) | 1.1 GB | 1.3 GB |

## Capacity

- Isolated cost is 0.18 ms per match-tick, so one core at 100 % runs about 85 matches. The spec's
  alert line is p99 tick under 10 ms; at 70 % utilisation that is about 60 matches per core.
- **200 concurrent matches need about 3.5 dedicated cores.** That means one 8-vCPU match host, or
  two 4-vCPU hosts, with headroom.
- This 4-vCPU container also renders screenshots in software, so it cannot hold 200 matches in real
  time: it falls behind on 38 % of ticks.
- Memory is about 6.5 MB per match. Egress is 64 kbit/s per client, about 128 Mbit/s for 2,000
  clients.

## Next

- A snapshot delta against `baseTick` would roughly halve egress. The field already exists in the
  protocol and is unused.
- Symmetric LOS reuse (A→B for B→A) and a coarse PVS per map area would cut sight cost further.
